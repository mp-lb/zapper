Local dev stacks keep getting less local.

API, frontend, worker, database, cache, tunnel, seed script.

`zap.yaml`

## 22. Cloud Agent Costs

Most cloud agent setups are paying for isolation with latency, infra, and complexity.

Zapper keeps the isolation model, but runs locally with lightweight process + port management instead.

https://zapper.mp-lb.dev


## 23. Local-First Isolation

Giving every coding agent its own cloud instance works.

It is also expensive, slower, and operationally annoying.

Zapper takes the same "one isolated environment per agent" idea and makes it local-first.

https://zapper.mp-lb.dev


## 24. Clean Isolated Workspace

The interesting part is not "run agents in the cloud."

The interesting part is giving every agent a clean isolated workspace.

Zapper does that locally without Dockerfiles, container orchestration, or infra overhead.

https://zapper.mp-lb.dev


## 25. Agent Conflicts

Coding agents conflict when they share ports, logs, processes, and state.

Cloud sandboxes solve that with infrastructure.

Zapper solves it locally with isolated project instances and automatic port management.
